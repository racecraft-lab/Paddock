Peer Review Checklist

Review visual diffs the same way every time, and leave comments that engineers can act on directly.

  1. 1
    Open the PR workflow artifacts first. Use the current PR run, not an older main baseline. Check both Playwright and Storybook reports when both workflows ran.
  2. 2
    Confirm manifest gates before judging pixels. Playwright must verify 149 snapshots across 118 tests; Storybook must verify 152 snapshots across 152 stories.
  3. 3
    Scan by domain, then by risk. Start with governance and cost-tracker states, then review Product Line, feature flags, Ready for Owner, and SPEC-007 surfaces.
  4. 4
    Approve intentional changes only. Expected diffs should match the spec, PR description, or linked task. Clipped controls, wrong seed data, a11y regressions, and layout shifts are blockers.
  5. 5
    Comment with file, state, and screenshot name. Use the template below so the author can reproduce the exact failing surface without searching through artifacts.

Decision Guide

Keep review comments focused on visual risk, not general taste.

Approve

  • Text, spacing, and data changes match the PR scope.
  • Responsive states remain usable and unclipped.
  • Manifest counts and domain coverage are green.

Request Changes

  • Controls overlap, clip, wrap poorly, or disappear.
  • Seed data, timestamps, or loading states look unstable.
  • Diffs affect unrelated domains or unmentioned journeys.
